# 知識管理規則

本文件定義 `doc/` 目錄下所有知識文件的新增、修改與維護規則。任何對 `doc/` 的操作都應遵循以下規範。

---

## 1. 語言規範

- 所有內容**必須**使用**繁體中文**撰寫。
- 專有名詞、程式碼關鍵字、函式名稱、原文無適當翻譯之術語，可保留原文並以括號附加對照。
  - 範例：`依賴注入（Dependency Injection, DI）`、`快取（Cache）`
- 禁止使用簡體中文、注音文、火星文等非正式書寫形式。

---

## 2. 分類與歸檔規則

### 2.1 知識分類目錄

知識文件必須依其性質放入對應的分類目錄中。目前定義的頂層分類如下：

| 目錄 | 適用內容 |
|------|----------|
| `00-知識庫核心/` | 知識管理規則、分類標準、範本等管理知識庫本身的文件 |
| `01-開發技術/` | 程式語言、嵌入式開發、系統設計、資料庫等所有技術主題 |
| `02-開發工具與流程/` | Git、Docker、編輯器設定、CI/CD、開發工作流程 |
| `03-科普新知/` | 科學普及、新技術趨勢、跨領域知識、科普書籍筆記 |
| `04-人文閱讀/` | 文學、小說、散文閱讀筆記與心得 |

### 2.2 分類原則

1. **符合性優先**：新文件應先檢查現有分類中是否有合適的目錄。
2. **就近歸類**：若內容涵蓋多個分類，選擇最主要的那一個，並在文件中透過 `[[wikilink]]` 關聯到其他相關文件。
3. **新增類別**：若現有分類均不適合，可在合適的父層級下新增目錄。新增後必須同步更新本文件的「知識分類目錄」表格。
4. **一層原則**：目錄深度以 2~3 層為限，避免過深造成維護困難。

---

## 3. 新增與合併規則

### 3.1 新增前檢查

新增任何文件前，必須先執行以下檢查：

1. **全文搜尋**：使用關鍵字搜尋整個 `doc/` 目錄，確認是否已有相關內容。
2. **關聯檢查**：檢查 [[目錄結構與分類標準]] 中定義的分類，確認是否已有相似主題文件。
3. **交叉比對**：透過 Obsidian 圖譜（Graph View）檢視相關文件之間的連結關係。

### 3.2 合併原則

若發現已有相關內容：

1. **優先整合**：將新增內容整合到現有文件中，而非另開新檔。
2. **禁止刪減**：除非特別要求，否則整合時**不得移除或刪減**原有內容。僅能補充、擴充或重組。
3. **附加保留**：若為觀點補充或不同面向的探討，應以新增章節（Heading）的方式附加，保留完整脈絡。
4. **連結取代複製**：若兩份內容高度相關但主題明確可分，應使用 `[[Page Name]]` 或 `[顯示文字](path/to/file.md)` 進行關聯，避免重複撰寫相同內容。

### 3.3 衝突處理

若新增內容與既有內容觀點不一致：

1. 在文件中並列呈現不同意見，標註各自來源或背景。
2. 使用 `> [!NOTE]`、`> [!WARNING]` 等 Obsidian Callout 來標示爭議或待確認事項。
3. 勿擅自刪除或覆蓋他人撰寫的內容。

## 4. Obsidian 格式規範

因本文件庫使用 Obsidian 作為閱讀工具，所有 `.md` 文件必須遵守以下格式：

### 4.1 Frontmatter（後設資料）

每個文件開頭必須包含 YAML frontmatter：

```yaml
---
title: 文件標題
tags:
  - tag1
  - tag2
created: YYYY-MM-DD
modified: YYYY-MM-DD
aliases:
  - 別名1
  - 別名2
---
```

- `title`：文件標題（必填）
- `tags`：標籤清單（建議填寫，用於分類篩選）
- `created` / `modified`：建立與修改日期（格式 `YYYY-MM-DD`）
- `aliases`：別名（選填，便於透過不同名稱連結到此文件）

### 4.2 內部連結（Wikilinks）

- 檔案間連結使用 `[[檔案名稱]]` 或 `[[檔案名稱|顯示文字]]`。
- 連結到特定標題：`[[檔案名稱#章節標題]]`。
- 嵌入其他檔案內容：`![[檔案名稱]]`。

### 4.3 標籤（Tags）

- 文件內可使用 `#tag` 進行標記。
- 標籤建議使用英文或英文+數字，避免中文標籤的路徑編碼問題。
- 建議 tags 層級：`#area/技術`、`#topic/嵌入式`、`#status/進行中`。

### 4.4 Callout 提示區塊

使用 Obsidian Callout 格式標註特殊資訊：

```
> [!NOTE] 一般提示
> 補充說明或注意事項

> [!WARNING] 警告
> 需要注意的潛在問題

> [!TIP] 技巧
> 實用建議或最佳做法

> [!IMPORTANT] 重要
> 必須遵守的關鍵事項

> [!CAUTION] 小心
> 可能導致錯誤的操作
```

### 4.5 程式碼區塊

所有程式碼範例必須使用圍欄式程式碼區塊（fenced code block），並標註語言：

````
```python
print("Hello")
```
````

### 4.6 檔案命名規則

- 檔案名稱應簡潔且具描述性。
- 使用全形字元（中文）或連字號 `-` 連接英文單字。
- 避免使用空白、特殊符號。
- 範例：`快取策略.md`、`api-authentication.md`

---

## 5. 例外與豁免

- 若因特殊原因無法遵守上述規則（如引用外部原文資料、自動產生的文件等），應在文件 frontmatter 中加入 `exempt: true` 並於首行說明原因。
- 任何規則修改須經團隊討論決議，並在此文件記錄變更歷程。
