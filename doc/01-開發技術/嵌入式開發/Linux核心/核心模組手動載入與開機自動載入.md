# 核心模組手動載入與開機自動載入

---

## 手動載入模組

### `modprobe` vs `insmod` 差異

| 工具 | 說明 |
|------|------|
| `modprobe` | 載入指定模組及其依賴，依賴 `/lib/modules/$(uname -r)/modules.dep` |
| `insmod` | 直接載入指定模組，不檢查依賴關係 |

### 常見問題：modprobe 找不到模組

```
modprobe: FATAL: Module iptable_raw not found in directory /lib/modules/5.15.148-tegra
```

**原因：**
- 模組檔案未註冊：未執行 `depmod`，導致 `modprobe` 找不到
- 核心版本不匹配

**解決方法：**

1. 將模組放入正確路徑：
   ```bash
   sudo cp iptable_raw.ko /lib/modules/$(uname -r)/kernel/net/ipv4/netfilter/
   ```

2. 更新模組依賴關係：
   ```bash
   sudo depmod -a
   ```

3. 使用 `modprobe` 載入：
   ```bash
   sudo modprobe iptable_raw
   ```

4. 確認核心版本：
   ```bash
   uname -r
   ```

## 開機自動載入模組

### 透過 systemd 的 modules-load.d

```bash
echo iptable_raw | sudo tee /etc/modules-load.d/iptable_raw.conf
```

此設定檔會在開機時由 `systemd-modules-load.service` 讀取，執行 `modprobe iptable_raw`。

### 其他自動載入機制

| 機制 | 說明 |
|------|------|
| **核心自動載入** | 偵測到硬體或系統事件時自動載入（USB、網卡），由 udev 或 hotplug 觸發 |
| **initramfs/initrd** | 開機初期由 initramfs 載入必要模組 |
| **modprobe.d/** | 透過 `/etc/modprobe.d/` 設定檔間接載入 |
| **系統服務或腳本** | 由 systemd service 或開機腳本載入（如 NVIDIA 驅動） |

## 驗證

```bash
# 確認模組已載入
lsmod | grep iptable_raw

# 查看開機紀錄
journalctl -b | grep iptable_raw
```

## 模組路徑原則

核心模組應放在 `/lib/modules/$(uname -r)/kernel/<subsystem>/<category>/` 下：

- 網路相關：`kernel/net/ipv4/netfilter/`
- 檔案系統：`kernel/fs/`
- 驅動程式：`kernel/drivers/`

> `depmod` 只會掃描 `/lib/modules/$(uname -r)/` 下的內容，放在其他路徑無法被 `modprobe` 識別。
