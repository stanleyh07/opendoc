# 改善說明：4K 螢幕 scale 1080p 時 AI 繪圖鋸齒問題

## 背景

在 4K（3840×2160）螢幕上設定為 1080p（1920×1080）輸出時，AI 模型繪製在畫面**上層的裝飾圖層**（方框、骨架線條、關鍵點、文字標籤）會出現明顯的**鋸齒狀、邊緣破碎、線條歪斜**等問題。

這份文件說明根本原因以及修改方式。

---

## 問題一：繪圖引擎用錯畫筆（LINE_4 → LINE_AA）

### 原本的寫法

```cpp
cv::rectangle(image, topLeft, bottomRight, color, thickness, cv::LINE_4);
```

`cv::LINE_4` 是古老的 **4-連通 Bresenham** 繪圖演算法。

### 特性

每一筆只往 **4 個方向**（上、下、左、右）延伸，遇到斜線時只能以階梯狀的方式呈現：

```
LINE_4 畫一條斜線：
█
 █
  █
   █
```

沒有**反鋸齒**處理，邊緣是 100% 全亮 → 0% 全暗的突然跳變。

### 為什麼放大後會變破碎

```
1080p 畫布上 1px 線條      放大 2× 到 4K 螢幕（視覺上）

  ██                         ████
   ██                         ████
    ██                         ████
     ██                         ████
                                  ████
                                   ████
                                    ████
```

1~2 像素粗的階梯狀邊緣，在放大 2× 後階梯被放大，人眼更容易察覺。

### 修改方式

```cpp
cv::rectangle(image, topLeft, bottomRight, color, thickness, cv::LINE_AA);
```

`cv::LINE_AA` 啟用**反鋸齒（Anti-Aliasing）**。

### 原理

在繪圖時計算邊緣的**透明度漸層**，讓像素之間的亮度平滑過渡，欺騙人眼以為看到的是平滑線條：

```
LINE_AA 畫同一條線（灰階值，0=黑，255=白）：

原始繪圖資料：
  0   0   0   0   0   0   0   0
  0  50  200  50   0   0   0   0
  0   0  50  200  50   0   0   0
  0   0   0  50  200  50   0   0

視覺呈現：
  ░░░░░░░░
  ░▓████░░
  ░░░▓███░
  ░░░░▓██░
```

邊緣從黑色平滑過渡到白色，而非突然跳變。

### 影響範圍

| 元件 | 修改前 | 修改後 |
|------|--------|--------|
| 邊界框四邊 | `LINE_4` | `LINE_AA` |
| 骨架連線 | `LINE_4` | `LINE_AA` |
| 骨架關鍵點 | 無反鋸齒 | `cv::circle` + `LINE_AA` |
| 類別名稱文字 | 無反鋸齒 | `cv::putText` + `LINE_AA` |

**總計修改 10 處繪圖呼叫。**

## 問題二：座標用「捨去」而非「四捨五入」

### 原本的寫法

AI 模型回傳的是**浮點數座標**（例如 `x_min = 47.7`），繪圖必須轉換成整數像素位置：

```cpp
x_min = (int)((bbox.x_min - padding) / ratio);
```

`(int)` 是 C++ 的**無條件捨去（truncation）**，直接去掉小數部分。

### 問題

| 實際值 | `(int)` 結果 | 誤差 |
|--------|-------------|------|
| 47.3 | 47 | -0.3 pixel |
| 47.7 | 47 | **-0.7 pixel** |
| 47.1 | 47 | -0.1 pixel |
| 47.9 | 47 | **-0.9 pixel** |

最大誤差高達 **0.999 pixel**。

### 為什麼放大後更嚴重

在 1080p 畫布上 0.7 pixel 的偏移看起來不明顯，但整張畫面被放大 2× 到 4K 時：

- 偏移也跟著放大 → 變成 **1.4 pixel**
- 方框的四個角各自有不同程度的偏移
- 方框變得不對稱、線條歪斜

### 修改方式

```cpp
x_min = static_cast<int>(std::round((bbox.x_min - padding) / ratio));
```

`std::round()` 執行**四捨五入**（0.5 以上入、以下捨）。

### 改善

| 實際值 | `std::round` 結果 | 誤差 |
|--------|------------------|------|
| 47.3 | 47 | -0.3 pixel |
| 47.7 | **48** | **+0.3 pixel** |
| 47.1 | 47 | -0.1 pixel |
| 47.9 | 48 | +0.1 pixel |

最大誤差從 **0.999 pixel** 降至 **0.499 pixel**，改善 **50%**。

**總計修改 26 處座標計算。**

---

## 兩個問題的疊加效應

放大 2× 時，兩者疊加後的差距更明顯：

```
修改前（LINE_4 + truncation）：

1080p 畫布                 4K 螢幕（放大 2×）
┌──┐                       ┌────┐
│█ █│  ← 1px 偏移、鋸齒     │██ ██│  ← 變成 2px 偏移、鋸齒放大
│ █ │                       │ ██ │
└──┘                       └────┘

修改後（LINE_AA + std::round）：

1080p 畫布                 4K 螢幕（放大 2×）
┌──┐                       ┌────┐
│▓ ▓│  ← 精確位置、平滑邊緣  │▓▓ ▓▓│  ← 維持平滑
│ ▓ │                       │ ▓▓ │
└──┘                       └────┘
```

---

## 一句話總結

原本問題是**用粗糙的畫筆（LINE_4）在不準確的位置（truncation）畫圖**，然後整張圖被放大 2× 到 4K 螢幕；改善後改為**用平滑的畫筆（LINE_AA）在精確的位置（std::round）畫圖**，放大後仍然維持平滑。

---

## 關於 8K 螢幕

這些改善是**演算法層級**的變更，與螢幕解析度無關：

- 應用程式始終 scale 成 1080p 輸出，繪圖都在 1080p 畫布上完成
- 8K（7680×4320）相當於 1080p 放大 **4×**，反鋸齒的效果只會更明顯
- 唯一的潛在問題是 Qt DPR 偵測，可透過環境變數強制解決
