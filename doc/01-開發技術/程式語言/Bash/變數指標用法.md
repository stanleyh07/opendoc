如果想使用變數存放變數名稱，並用這個變數名稱去取得變數內容

比如，要檢查多個環境變數是否有設定
```bash
check_config()
{
	unset missing
	for var in $@; do
		eval [ -z \"\$$var\" ] || continue

		missing="$missing $var"
	done

	[ "$missing" ] || return 0

	notice "Skipping $(basename "${BASH_SOURCE[1]}") - ${FUNCNAME[1]} for missing configs: $missing."
	return 1
}
```

### 為什麼使用 `eval` 和 `$$var`

在迴圈中，`$var` 代表傳入的變數名稱，例如如果你傳入的變數名稱是 `VAR1` 和 `VAR2`，那麼在第一次迭代中，`$var` 會是 `VAR1`，第二次迭代中會是 `VAR2`。

`eval` 命令允許我們動態地解析並執行一個命令或表達式。在這個情況下，`eval [ -z \"\$$var\" ]` 這行的作用是檢查 `VAR1` 或 `VAR2` 是否為空。具體來說：

- `$$var`：`$` 表示變數解析，然後再解析一次 `$$var` 變成 `$VAR1` 或 `$VAR2`。
    
- `eval [ -z \"\$$var\" ]`：這行在 `eval` 執行時會變成 `[ -z "$VAR1" ]` 或 `[ -z "$VAR2" ]`，從而檢查這些變數是否為空。
    

所以，`$$var` 用來間接取得變數的內容，而 `eval` 是讓這個間接取得的變數能被正確地解析和執行。

結果就是
```bash
check_config RK_YOCTO RK_NETWORK_CHECK
```

然後 `$@` 會得到 `RK_YOCTO` `RK_NETWORK_CHECK`
而 `$var` 會依次得到 `RK_YOCTO` 和 `RK_NETWORK_CHECK`
`$$var` 等於是 `$RK_YOCTO` 和 `$RK_NETWORK_CHECK`
因此可以得到 `RK_YOCTO` 和 `RK_NETWORK_CHECK` 的內容

用法
使用 check_config 檢查 RK_YOCTO 是否設定，
若未設定，則利用 false 回傳 1 (錯誤)，並結束 build_yocto
```bash
build_yocto()
{
	check_config RK_YOCTO || false
	.....
}
```
