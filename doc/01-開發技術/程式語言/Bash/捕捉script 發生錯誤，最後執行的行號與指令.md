
## ⚡ 為什麼需要定位錯誤？

當腳本開啟 `set -e` 模式時，任何指令只要回傳值不為 0（失敗），腳本會立即中斷。為了避免「無聲的崩潰」，我們需要機制來捕捉最後執行的行號與指令。

---

## 🛠️ 核心解決方案

### 1. 自動化捕捉：使用 `trap` 指令 (推薦)

這是最完整的做法，能在腳本崩潰瞬間自動噴出錯誤資訊。

- **機制**：監聽 `ERR` 信號。
    
- **程式碼範例**：
    
    Bash
    
    ```
    #!/bin/bash
    set -e
    
    # 定義錯誤處理函式
    error_handler() {
      echo "❌ 錯誤發生在第 $1 行：指令 '$2' 執行失敗。"
    }
    
    # 綁定 ERR 信號
    trap 'error_handler ${LINENO} "$BASH_COMMAND"' ERR
    
    # 測試錯誤
    ls /nonexistent_path
    ```
    

### 2. 即時追蹤：使用 `set -x`

適合在開發階段快速觀察執行流。

- **用法**：在腳本開頭加入 `set -ex`。
    
- **效果**：終端機會印出每一行執行前的指令，腳本停在哪一行，那行就是錯誤點。
    
- **進階設定**：調整 `PS4` 變數可以讓輸出的追蹤資訊包含行號：
    
    `export PS4='+(${BASH_SOURCE}:${LINENO}): '`
    

### 3. 手動檢查：使用 `$LINENO` 變數

如果你只想在特定的關鍵步驟進行監控。

- **用法**：直接在 `echo` 或 `exit` 中調用內建變數 `$LINENO`。
    

---

## 📋 方案對比表

|**方案**|**複雜度**|**優點**|**缺點**|
|---|---|---|---|
|**Trap ERR**|中|訊息最清楚，適合正式腳本|需要額外撰寫處理函式|
|**set -x**|低|隨插即用，完整看到執行流程|輸出資訊量大，較混亂|
|**$LINENO**|低|適合手動精準標註|每個步驟都要寫，維護麻煩|

---

## 💡 進階建議：補全安全性

除了定位行號，建議將腳本開頭的設定改為：

Bash

```
set -eo pipefail
```

- **`-e`**: 遇錯即停。
    
- **`-o pipefail`**: 確保管線指令（如 `A | B`）中若 A 失敗，整個管線也會被視為失敗。
